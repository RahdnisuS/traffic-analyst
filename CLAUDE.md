# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Traffic Analyst": a road-junction simulator with reinforcement-learning signal control, a LightGBM predictor and an LLM (RAG) analyst, built as a portfolio project in 14 phases. Phases 1–12 are done (headless sim, metrics + run logs, FastAPI/WebSocket dashboard, mixed traffic + pedestrians, 2.5D Three.js view, stress test + capacity benchmark, PPO signal controller that beats the fixed timer and a gap-out rule, AI switch + side-by-side comparison in the dashboard, LightGBM queue predictor with dashed forecast lines, 5-controller experiment over 90 paired scenarios, RAG knowledge base with hybrid retrieval, analyst chat tab with grounded answers and scenario proposals). Next: Phase 13 (RAG evaluation with RAGAS).

**`docs/SPEC.md` is the project spec: always read the relevant phase in it before starting a phase.** It holds the original brief (all 14 phases, tech stack, working rules), a decision log that overrides the brief where they differ, and a status checklist. When a phase lands, update both its Status list and the README's. Record new design decisions in its decision log.

Workflow: after each phase, stop, summarise, explain the concepts simply, commit, and wait for the user's go-ahead. Ask before major design decisions the spec doesn't cover. Keep the "why" comments in the code — the user has to explain every design decision in interviews.

## Commands

Python 3.13 venv at `.venv` (Windows: `.venv/Scripts/activate`).

```bash
pip install -r requirements.txt     # deps are grouped by phase; later phases append theirs
python -m sim --duration 900        # headless run; flags: --seed, --config, --report-every, --no-log, --runs-dir
python -m server                    # dashboard at http://127.0.0.1:8000 (--host, --port; PORT env var wins)
python -m bench                     # capacity benchmark, ~70 s (--seeds, --workers, --quick smoke test, --no-save, --out)
python -m rl.train                  # train MaskablePPO, ~18 min on 14 processes (--quick smoke test, --timesteps, --n-envs)
python -m rl.evaluate               # trained agent vs fixed timer and gap-out on held-out seeds
python -m sim --controller rl       # headless run with the trained agent (needs rl/models/ppo_signal.zip)
python -m predict.generate          # log the predictor dataset into data/predictor_runs/ (~90 s; --runs, --run-s, --overwrite)
python -m experiments               # 5 controllers x 90 scenarios, ~5 min (--quick, --scenarios, --measure-s, --workers, --out)
python -m rag.build                 # index docs/**/*.pdf + data/runs/ into chroma/ (incremental; --rebuild, --docs-only, --runs-only)
python -m rag.search "query"        # try retrieval (--mode vector|bm25|hybrid|hybrid_rerank, --source doc|run, --run ID, --full)
python -m predict.train_predictor   # train LightGBM (~15 s) -> predict/models/queue_lgbm.txt + experiments/results/predict/<ts>/
pytest -q                           # all tests
pytest tests/test_idm.py::test_name # single test
```

## Architecture

- **`config.yaml` is the single source of truth** for every tunable parameter, validated by Pydantic in `sim/config.py` (unknown keys are errors). Add new parameters there rather than hard-coding them. Units: metres, seconds, m/s, vph.
- **Junction geometry is data**: `junctions/*.json` (arms, lane counts, allowed movements per lane, signal phases) is loaded by `sim/junction.py`, which builds lane edges, turning connectors, the conflict sets between connectors, and phases.
- **`sim/engine.py` `Simulation.step()`** advances by `dt` with no I/O or wall-clock time: signal policy → spawner → pedestrians → insertion → bike filtering → leader finding → vectorised IDM (`sim/idm.py`) → integration/edge transitions. Junction entry uses a reservation ("box-junction") rule: commit only on green (or amber when unable to stop), with no conflicting path occupied or reserved, room in the exit lane, and nobody walking on a crosswalk the path crosses.
- **Edge kinds**: `inbound`, `filter` (`flt_*`: bike-only virtual lane on a lane divider; exit-side twins `oflt_*` are kind `outbound`), `connector`, `outbound`. Code that means "ends at a stop line" uses `Edge.is_approach` / `junction.approach_edges()` / `approach_lanes(arm)`, not `kind == "inbound"`. Conflicts are computed from geometry (filter-lane paths use a smaller threshold). `junction.filter_movements` derives which movements may filter.
- **Vehicle types** (car/bike/auto/bus) differ by IDM parameters plus two flags in `VehicleTypeParams`: `filters` (bikes) and `kerb_lane` (buses). `Vehicle.lat_shift` is drawing-only (smooth swerve into a filter gap); render positions come from `Simulation.lane_poses()`, whose heading is the chord rear-point -> front-point (so long vehicles sit on the path through turns).
- **Box occupancy is by body, not nose**: `connector_users()` maps each connector to the vehicle types with any part of their body on it (plus committed reservations). Entry checks `Junction.conflicts_for(cx, type, other_cx, other_type)` = centreline conflicts OR per-type-pair swept-body conflicts. Approach-lane drivers also follow a "turned-off leader" (same lane, different connector) until its rear clears; bikes in a filter gap don't overtake vehicles too wide to share it, and a turning wide vehicle waits for a bike beside or ahead of it.
- **Pedestrians** (`sim/pedestrian.py`): `social_force()` is the pure, vectorised model (elliptical specification); `PedestrianSystem` runs the APPROACH → WAIT → CROSS → LEAVE lifecycle. Walkers and vehicles are separated by rules, not forces.
- **Determinism is a hard invariant**: all randomness comes from one seeded `np.random.Generator`, and loops iterate in a fixed order. Same seed + config gives a bit-identical run (`Simulation.fingerprint()`; tested). Don't introduce unseeded randomness or set/dict-order-dependent iteration.
- **Signals**: `SignalController` (`sim/signals.py`) owns the green → amber → all-red stages and enforces `min_green_s`. It also inserts the exclusive pedestrian phase (WALK → PED_CLEAR → all-red, phase name `"PED"`) when called, at most once every `min_greens_between` greens. Use `signals.phase_name` for display/logs (`signals.phase` is the last vehicle phase). Policies implement the `SignalPolicy` protocol (`update(controller, sim)`) and can only *request* switches: `FixedTimePolicy` (per-phase greens), `ActuatedPolicy` (detector zone + passage time + max green, config `actuated:`), `rl.env.GapOutPolicy`, and `rl.policy.RLPolicy` (`signals.controller: rl`), which therefore can't break min green, amber, all-red or the pedestrian phase. `RLPolicy(max_green_s=...)` forces a switch after `rl.max_green_s` (60) of green and logs `forced: "max_green"`; every production construction passes `cfg.rl.max_green_s` (None = unguarded, used by the training-parity tests). `webster_timing()` computes a Webster fixed plan.
- **Observers**: `MetricsCollector` (`sim/metrics.py`) samples queues, delay, throughput and LOS, and detects episodes (queue spike, spillback, gridlock) with on/off hysteresis. `MetricsCollector.after_step()` returns `(row, events, trips, ped_trips)`. `RunLogger` (`sim/logger.py`) writes `data/runs/<timestamp>_<controller>_s<seed>/` containing `manifest.json` (schema v3), `metrics.csv`, `trips.csv`, `peds.csv`, `events.jsonl` and `decisions.jsonl` (RL decisions; empty for the fixed timer). These logs are what later phases (predictor, RAG) consume.
- **Benchmark** (`bench/`): `stress.py` ramps demand with independent runs per level and judges each with `judge()` + `stock_growth()`: per approach, arrivals - departures = stock growth (conservation; stock = on the road + spawner backlog), measured between cycle-averaged stocks because queues are a sawtooth. "Breakdown" is oversaturation, not gridlock (the box-junction rule prevents literal gridlock). Results go to `experiments/results/benchmark/<timestamp>_s<seeds>/` (committed); `latest_summary()` reads the newest. `live.py` `LiveStressTest` is a session observer that ramps the running dashboard sim with the same judging, emits `stress_start/step/result` events via `MetricsCollector.custom_event()`, and restores the user's volume. While it runs the server rejects `settings` commands.
- **RL** (`rl/`, needs torch + gymnasium + stable-baselines3 + sb3-contrib; `sim/` never imports it): `features.py` is the single definition of the 15-number PHASE-RELATIVE observation (green, next, next2, next3 slots), the `DecisionClock` (fixed 5 s grid) and `waiting_now()` (stopped vehicles + backlog), shared by training and deployment (parity is tested). `env.py` `SignalEnv`: one step = one keep/switch decision = exactly 5 s; `action_masks()` offers "switch" only when `can_switch()`; reward = -waiting vehicle-seconds/100 - 0.2 per switch; traffic randomised per episode (`episode_traffic`), `make_sim()` builds a sim for given traffic so baselines face identical conditions. `policy.py` `RLPolicy` is a `SignalPolicy` that requests switches and appends a record per decision to `sim.decisions` (-> `decisions.jsonl`). `train.py` (MaskablePPO, SubprocVecEnv, VecNormalize on rewards only) writes progress.csv, greedy_eval.csv + training_curve.png (fixed-timer and gap-out baselines; the agent both while exploring and greedily every `rl.curve_eval_every` decisions on the same episodes) to `experiments/results/rl/<timestamp>/` and the model to `rl/models/ppo_signal.zip` (gitignored). `evaluate.py` compares against the fixed timer and `env.GapOutPolicy` and writes evaluation.md/json into the same folder.
- **Experiments** (`experiments/compare.py`, `python -m experiments`): `make_scenarios()` (seeded, per band), `measure_saturation_flow()` (stop-line counter probe), `webster_plan()`, `run_one()` (warm-up then scored window; waiting = `waiting_now`, delay, served %, worst queue, ped wait, greens/h), `analyse()` (mean/std per band; `paired()` = per-scenario % change, bootstrap CI, wins, Wilcoxon), report.md + CSVs + plots to `experiments/results/comparison/<ts>/` (committed).
- **Analyst** (`rag/analyst.py` + `rag/llm.py`, `rag/grounding.py`, `rag/scenario_parser.py`; served by `server/analyst.py` `AnalystService` at `POST /api/chat` and `GET /api/analyst`): `Analyst.ask(question, history, AnalystContext)` -> route (JSON) -> `_retrieve` by intent -> answer from numbered sources -> `unsupported_numbers` check, one repair, leftovers returned in `grounding`. Returns `{"type": "answer"|"scenario"|"error", ...}`; every exchange appended to `analyst.log_path`. `AnalystService` flushes the live run loggers, re-indexes the live run(s) in a worker thread, builds the live-status source (incl. `_measured_timing`), and serialises questions with a lock. `GroqClient` (httpx; key from env/.env; fallback model on 429; raises `LLMError` with user-facing text). Tests use a scripted fake LLM (`tests/test_analyst.py`). Frontend: `web/chat.js` `Chat` (escape-then-markdown rendering, citation buttons, scenario card -> `settings`/`controller` WS commands); tabs in `app.js` (`setTab`).
- **RAG** (`rag/`; `sim/` never imports it): `chunking.py` (`Chunk`, `pack_word_spans`, BM25 `tokenize` keeping "3:20" and decimals), `ingest.py` (PyMuPDF pages -> cleaned paragraphs with section -> chunks citing the PRINTED page; catalogue `rag/sources.yaml`; bump `INGEST_VERSION` when cleaning changes), `run_indexer.py` (run log -> `run_summary` / `run_window` / `rl_decisions` prose chunks per `rag.run_window_s`; every number from the log), `embeddings.py` / `rerank.py` (lazy-loaded sentence-transformers models; tests inject fakes), `vectorstore.py` (Chroma wrapper, our own embeddings, cosine; `to_where`/`matches` = the same equality filter for Chroma and BM25), `retrieval.py` (`Retriever.search(query, k, mode, filters)` -> `Hit`s with per-stage ranks; BM25 + vectors -> `rrf_fuse` -> cross-encoder; `time_ranges()` puts run windows covering a named time first), `build.py` (`KnowledgeBase`: incremental via `chroma/index_state.json`, `index_run()` for live runs). Chunk metadata: `source_type` doc|run, `kind`, `citation`, doc_id/page/page_label/section or run_id/t_start/t_end. PDFs are gitignored (`docs/**/*.pdf`).
- **Predictor** (`predict/`, needs lightgbm; `sim/` never imports it): `features.py` is the single definition of the per-approach features, computed from metrics ROWS (`History` = the needed columns as arrays; `features_at(h, i, ctx)` -> one row per arm, sorted) plus a `Context` (controller, demand, ped rate, green time) from the manifest config offline or `sim.cfg` live. Look-backs are capped at `LOOKBACK_S` = 300 s with zero padding before the run, so the live window (last 301 rows) matches the log exactly (parity tested). `generate.py` logs `predict.dataset_runs` runs (random traffic, controllers fixed/gap_out/rl round-robin, split tag train/val/test by index) into `data/predictor_runs/`; `train_predictor.py` trains LightGBM (L1, early stopping on val) and scores MAE vs persistence and the recent 2-min mean on test, writing report.md/metrics.json/plot.png to `experiments/results/predict/<ts>/` and the model (+ .json meta incl. feature list) to `predict/models/` (gitignored). `forecaster.py` `QueueForecaster` refuses a model with a different feature list.
- **Server** (`server/`): one shared `SimSession` (main loop `run_loop()`) is advanced by a single asyncio task at 20 Hz using a "time debt" so speed is exact on average; it drops debt rather than spiralling when it falls behind. Each client has an outbox where position frames are latest-wins and metrics/events are reliable and ordered. The same collector output feeds both the logger and the browsers, so the dashboard and logs always agree. Client commands are Pydantic models in `server/schemas.py`. Commands include `{"cmd": "stress", "action": "start"|"stop"}`, `{"cmd": "controller", "value": "fixed"|"rl"}` (live hand-over) and `{"cmd": "compare", "action": "start"|"stop", "keep": "fixed"|"rl"}`; `status` carries `stress`, `controller`, `ai_available`, `compare`; `init` carries `benchmark` (latest official score), `analyst` (`AnalystService.status()`), `predictor` (horizon + held-out MAE, or null) and `forecast_history`; `metrics` carries `forecast` (list of `{t: from_t + horizon, from_t, N, E, S, W}`), main run only and not while comparing (`_attach_forecaster`). Each streamed sim is a `LiveRun` (sim + collector + logger + buffers + comparison totals); `session.run` is the main run, `session.twin` the AI run while comparing (both stepped in lockstep; settings go to both). In compare mode `frame` has a `twin` frame, `metrics` has `twin_rows` + `compare`, `events` has `twin_events`, `init` has `twin_history`/`twin_events`. The RL model is loaded once in a worker thread (`_ensure_model`). REST: `/api/health`, `/api/layout`, `/api/runs`, `/api/runs/{id}`, `/api/benchmark`; WebSocket: `/ws/sim`; `web/` is served statically at `/`.
- **Frontend** (`web/`): plain JS, no build step. `interp.js` interpolates between the two latest frames (entity interpolation) for vehicles and pedestrians, `render2d.js` draws the 2D debug canvas, `render3d.js` the 2.5D Three.js view (default; lazy-loaded via the import map in `index.html`, falls back to 2D), `geometry.js` holds layout helpers both share, and `charts.js` draws the live charts. `app.js` draws only the visible view; in compare mode it also draws the twin pane's renderer (created on first use) and copies the camera from whichever pane the user last touched (`syncCameras`). `charts.setCompare()` switches both charts to two lines (fixed vs AI). `charts.setForecast(horizon)` enables the 4 dashed forecast datasets (`forecast: true`, excluded from legend/end labels) and extends the queue chart's x-axis `horizon` s past now (`nowLine` plugin). Renderers only consume server state, which is: the `init` message (`layout` from `Junction.describe()` incl. `crosswalks` and `sidewalk_width`, `vehicle_types`, `vehicle_dims` [length, width], `ped_radius`) and each `frame`: `vehicles` as `[id, x, y, heading, speed, typeIdx]`, `peds` as `[id, x, y, state]` (0 approach, 1 wait, 2 cross, 3 leave), `signals` per arm (G/Y/R), `ped_signal` (walk/flash/dont_walk), `phase`, `stage`. Vehicle x/y is the FRONT bumper.

## Conventions / decisions

- Left-hand (Indian) traffic; 4-phase split signalling (one approach green at a time); lane counts come from the junction JSON.
- Safety invariants are tested every step (no overlaps, no red-light entry, no conflicting box paths, no vehicle onto an occupied crosswalk, `emergency_stops == 0`). `tests/test_bodies.py` also checks that no two vehicle RECTANGLES overlap anywhere (separating-axis test on the streamed poses), which is what catches collisions between different paths in the box. If a change makes `emergency_stops` non-zero, find the cause; don't relax the test. (Example: the red-light stop obstacle is placed from each vehicle's own `min_gap`, because bikes' small s0 parked them on the line.)
- `.env` holds `GROQ_API_KEY` (see `.env.example`) for the LLM phase; never commit it. `.claude/`, `data/runs/`, `data/predictor_runs/`, `chroma/`, `rl/models/*.zip` and `predict/models/` are gitignored.
